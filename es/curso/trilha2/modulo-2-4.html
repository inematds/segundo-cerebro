🚩 El flag --obsidian e --obsidian-dir

En el módulo 2.3 generaste el graph.json. Ahora vamos a convertirlo en un vault de Obsidian. El activador es una flag: dentro de Claude Code ejecutas el /graphify en tu fuente con --obsidian, y eso activa la exportación al vault. El --obsidian-dir dice dónde los archivos van a caer.

🔰 ¿Eres nuevo aquí? Skill vs. headless

Graphify tiene dos formas. La skill es el comando slash /graphify ejecutado dentro de Claude Code. El headless es la terminal pura, con graphify extract. Son el mismo motor, pero solo la skill conoce --obsidian.

⚠️ La trampa en la que muchos caen

--obsidian no existe en el graphify extract headless. Si intentas graphify extract . --obsidian en la terminal, no reconoce el flag. La exportación del vault es skill-only.

⚡ Práctico — copiar y ejecutar

Objetivo: transformar el grafo de tu fuente de documentación en un vault de Obsidian, eligiendo la carpeta de salida.

Claude Code (skill /graphify)
/graphify ./claude-code-docs --obsidian --obsidian-dir ~/vault/graphify/claude-code

./claude-code-docs e ~/vault/graphify/claude-code son <isto-voce-troca> — ajústalo a tu fuente y tu destino.

Cómo verificar: lista la carpeta de destino y verifica que aparezcan archivos.

ls ~/vault/graphify/claude-code | head

✓ Skill /graphify

  • ✓Conoce --obsidian e --obsidian-dir.
  • ✓También tiene --wiki, --update, --watch.
  • ✓Sin API key — usa el modelo de la sesión.

✗ Headless graphify extract

  • ✗No tiene --obsidian.
  • ✗Genera solo graphify-out/, sin vault.
  • ✗Pide ANTHROPIC_API_KEY.

🎯 Elegir el destino del vault

O --obsidian-dir define la carpeta donde nace el vault. Sin él, la skill crea su propio directorio, una especie de cuarentena aislada, lejos de tu vault principal. Es el comportamiento más seguro, pero elegir el destino ayuda a mantener todo organizado.

🔰 ¿Eres nuevo aquí? El «default aislado»

Sin --obsidian-dir, la exportación no invade tu vault de trabajo: va a una carpeta dedicada que puedes inspeccionar (y borrar) sin riesgo. Cuando tengas confianza, indica un destino fijo.

dos variantes
# destino que VOCÊ escolhe (organizado)
/graphify ./claude-code-docs --obsidian --obsidian-dir ~/vault/graphify/claude-code

# sem --obsidian-dir: a skill cria uma pasta própria (quarentena)
/graphify ./claude-code-docs --obsidian

↑ Ambas funcionan. La primera es predecible (sabes dónde encontrarlo); la segunda es a prueba de desorden — buena para la primera prueba. La ruta ~/vault/graphify/claude-code é <isto-voce-troca>.

🧾 Qué se genera (md por nodo + graph.canvas)

La exportación tiene dos partes. La primera: un archivo .md por nodo del grafo, cada uno con [[wikilinks]] para los nodos relacionados (que se convierten en backlinks). La segunda: un graph.canvas con las comunidades agrupadas. Juntas, forman el vault navegable.

🔰 ¿Eres nuevo aquí? Qué es un «wikilink»

Un wikilink es la sintaxis [[nome-da-nota]] de Obsidian: un enlace interno de una nota a otra. Cuando A enlaza B, Obsidian muestra en B un backlink ("quién apunta hacia mí"). Así es como el conocimiento se vuelve navegable mediante relaciones.

🔰 ¿Eres nuevo aquí? Qué es un «canvas»

Un canvas (archivo .canvas) es un tablero visual de Obsidian donde las notas se convierten en recuadros que puedes organizar libremente. El graph.canvas usa esto para mostrar cada comunidad como un grupo con nombre — la visión general del corpus.

↑ Un nodo del grafo = una nota .md; las relaciones se convierten en [[wikilinks]]; las comunidades se convierten en grupos en el graph.canvas. Los números (591 nodos) son ilustrativos — provienen de la ejecución del video.

♻️ Regeneración: ejecútalo de nuevo, rehace todo

La exportación es regenerado desde cero en cada ejecución, siempre a partir del graph.json. No hay que hacer merges manuales: el grafo es la fuente de verdad y el vault es solo un reflejo de él. Por eso, la operación es idempotente — ejecutarlo dos veces seguidas da el mismo resultado.

🔰 ¿Eres nuevo aquí? «Regeneración» e «idempotente»

Regeneración = el vault se recrea por completo en cada ejecución; no se actualiza parcialmente. Idempotente = repetir la operación no cambia el resultado después de la primera vez. A cambio, no necesitas pensar en el «estado anterior»: vuelve a ejecutarla cuando quieras.

⚠️ No edites a mano las notas generadas

Cómo se vuelve a generar la exportación desde cero, se pierde cualquier edición manual en las notas generadas en la próxima ejecución. ¿Quieres cambiar el contenido del vault? Cambia la fuente (los documentos) o el graph.json y vuelve a ejecutarlo: nunca el markdown de salida.

✓ Seguro

  • ✓Volver a ejecutar tantas veces como quieras.
  • ✓El vault siempre refleja el grafo actual.
  • ✓Sin estados intermedios inconsistentes.

✗ Se pierde

  • ✗Las notas editadas a mano se sobrescriben.
  • ✗Las anotaciones dentro de las notas generadas desaparecen.
  • ✗No hay merge: es todo o nada.

↑ Cada run reconstruye todo el vault a partir del grafo. Lo bueno: nunca queda "desactualizado". Algo que debes tener presente: las ediciones manuales no se conservan — la fuente es el grafo, no el markdown.

📚 --wiki como alternativa

Además del vault nodo a nodo, existe un segundo formato: --wiki. En vez de una nota por nodo, genera artículos por comunidad con un index.md de entrada: una lectura al estilo Wikipedia, útil para quien (persona o agente) prefiere leer textos continuos en lugar de navegar por recuadros.

⚡ Práctico — copiar y ejecutar

Objetivo: generar la versión wiki (artículos por comunidad) de la misma fuente para compararla con el vault.

Claude Code (skill /graphify)
/graphify ./claude-code-docs --wiki

./claude-code-docs é <isto-voce-troca> — apunta a tu fuente.

Cómo verificar: busca el index.md y los artículos en la carpeta de salida.

ls ~/vault/graphify/claude-code | head

🔰 Vault o wiki: ¿cuál usar?

Usa el vault (--obsidian) cuando quieras navegar por relaciones dentro de Obsidian. Usa la wiki (--wiki) cuando quieras leer artículos temáticos. No son excluyentes: puedes generar ambos y elegir después.

👀 Revisar el vault generado

Antes de abrir Obsidian, haz una comprobación rápida en el sistema de archivos: revisa la carpeta de destino, cuenta los archivos .md y confirma que el graph.canvas está ahí. Esto detecta exportaciones vacías o truncadas desde el principio, antes de que inviertas tiempo en la herramienta.

⚡ Práctico — copiar y ejecutar

Objetivo: confirma que la exportación haya generado las notas y el canvas en el destino correcto.

terminal
ls ~/vault/graphify/claude-code | head
ls ~/vault/graphify/claude-code/*.canvas

~/vault/graphify/claude-code é <isto-voce-troca> — usa el destino que pasaste en --obsidian-dir.

Cómo verificar: el primer comando debe listar varios archivos .md; el segundo debe encontrar exactamente un graph.canvas. Si la lista está vacía, la exportación falló; vuelve a ejecutar el paso del tema 1.
