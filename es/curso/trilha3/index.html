💬 Preguntarle a Claude Code usando el grafo

Con el vault en el proyecto, haz que el agente responda usando el mapa en vez de recorrerlo todo.

Qué es:

Deja el vault dentro del proyecto (o junto a él) e indica a Claude Code dónde está.

Por qué:

Solo usa lo que puede ver: si el vault no está en el contexto, es como si no existiera.

Conceptos:

Ruta del vault · contexto · proyecto.

Qué es:

Usar los god nodes de GRAPH_REPORT.md como punto de partida para las preguntas.

Por qué:

Los hubs cubren más terreno; empezar por ellos ayuda a completar el resto del mapa.

Conceptos:

Nodo God · hub · entrada.

Qué es:

Pedirle que siga los [[links]] de un concepto hacia los vecinos.

Por qué:

Respuestas conectadas, no aisladas: el agente recorre los alrededores en vez de detenerse en el primer nodo.

Conceptos:

Backlink · vecindad · navegación.

Qué es:

Prompt listo — "usa el vault en <pasta> para explicar X y sus conceptos relacionados, citando las notas".

Por qué:

Dirige al agente al grafo en lugar de dejarlo recorrer archivos a ciegas.

Conceptos:

Prompt · citar notas · alcance.

Qué es:

graphify --mcp expone tools query_graph, get_node, shortest_path.

Por qué:

El agente consulta el grafo mediante programación, sin depender solo de los archivos markdown.

Conceptos:

MCP · query_graph · resource.

Qué es:

Ir del concepto al documento fuente vinculado y comprobar si coincide.

Por qué:

Evita las alucinaciones y cierra el ciclo: la procedencia te lleva de vuelta a la evidencia.

Conceptos:

Procedencia · verificación · documento fuente.

🏛️ Construir un centro de control de Claude OS

Convierte el vault en un centro de comando: varios proyectos, conocimientos y dudas en un solo lugar.

Qué es:

Un vault principal que reúne proyectos, contenido y conocimiento importado en un sistema coherente.

Por qué:

El stack destaca cuando forma parte de un todo, no como grafos aislados.

Conceptos:

Centro de comandos · vault principal · sistema.

Qué es:

Estructurar el vault en proyectos/áreas y una carpeta de imports del grafo.

Por qué:

Cada cosa en su lugar, fácil de encontrar y de navegar para el agente.

Conceptos:

Similar a PARA · proyectos · importaciones.

Qué es:

Cada nuevo Graphify se agrega a una subcarpeta de import y se conecta con lo que ya existe.

Por qué:

El cerebro crece de forma controlada y curada, en vez de convertirse en un depósito.

Conceptos:

Subcarpeta · conexión · curación.

Qué es:

Crear notas puente que conecten el conocimiento importado con tus proyectos reales.

Por qué:

Saca el grafo del vacío: la tesis del video es que el conocimiento integrado vale más que el aislado.

Conceptos:

Nota-puente · contexto · integración.

Qué es:

Usar el agente para consultar, resumir y actualizar el vault del centro de comando.

Por qué:

El centro está vivo, no es estático: edita junto contigo.

Conceptos:

Copiloto · consultar · mantener.

Qué es:

Para code bases o consultas puntuales, puede ser mejor detenerse en Graphify.

Por qué:

No todos los casos requieren Obsidian: montar un centro solo para una pregunta es un overhead.

Conceptos:

Trade-off · silo · simplicidad.

🧭 Código vs. documentos: cuándo detenerse en Graphify

No todos los grafos tienen que ir a Obsidian. Aprende a decidir dónde parar.

Qué es:

Indicar a Graphify un repositorio de código (extracción AST mediante tree-sitter).

Por qué:

Mapea funciones/módulos sin API key: rápido y económico.

Conceptos:

Base de código · AST · tree-sitter.

Qué es:

Indicar docs/PDFs (extracción semántica mediante LLM).

Por qué:

Detecta conceptos y relaciones del texto, no solo la estructura literal.

Conceptos:

Corpus · LLM · semántica.

Qué es:

Para explorar una code base puntual, el graph.html + query ya bastan.

Por qué:

Llevarlo a Obsidian sería una carga adicional cuando solo quieres una respuesta rápida.

Conceptos:

Detente · graph.html · query.

Qué es:

Cuando el conocimiento necesita convivir con tus proyectos y notas.

Por qué:

Es el caso de uso del segundo cerebro integrado, no de un grafo aislado.

Conceptos:

Integrar · vault · contexto más amplio.

Qué es:

Usar graphify update/--watch a medida que cambian el código y la documentación.

Por qué:

El grafo no envejece: se mantiene fiel a la fuente.

Conceptos:

Actualización · observar · sincronizar.

Qué es:

Sopesar el tiempo de extracción, el ruido del grafo y el esfuerzo de mantener el vault.

Por qué:

Una decisión consciente, sin exageraciones: el costo es real.

Conceptos:

Costo · ruido · mantenimiento.

🛠️ Mantenimiento, actualización y solución de problemas

Mantén el grafo y el vault en buen estado y sabe qué hacer cuando algo sale mal.

Qué es:

graphify update . reprocesa solo lo que cambió; vuelve a exportar el --obsidian regenera el vault.

Por qué:

Mantener el estado actual sin rehacer todo desde cero.

Conceptos:

Actualización · volver a exportar · incremental.

Qué es:

La exportación de Obsidian se regenera desde cero; se pierden las ediciones manuales en las notas generadas.

Por qué:

Mantener tus notas en carpetas separadas (importaciones y tuyas) protege tu trabajo.

Conceptos:

Regeneración · separación · importaciones.

Qué es:

Ejecutar uv tool update-shell y volver a abrir la terminal.

Por qué:

El binario no está en el PATH; el shell necesita recargarse.

Conceptos:

PATH · shell · uv.

Qué es:

Configurar ANTHROPIC_API_KEY para uso headless; dentro del /graphify no hace falta.

Por qué:

Distinguir los dos caminos evita errores con la clave cuando ni siquiera hace falta.

Conceptos:

API key · headless · skill.

Qué es:

Limpiar la fuente, usar --mode deep o volver a definir el alcance.

Por qué:

Mejora las entidades/relaciones: mejor corpus, mejor grafo.

Conceptos:

Ruido · --mode deep · alcance.

Qué es:

Hacer commit graphify-out/ (o la bóveda) en git; usar la exportación del propio curso para guardar el progreso.

Por qué:

Reproducible y seguro: no pierdes lo que construiste.

Conceptos:

Git · copia de seguridad · reproducibilidad.
