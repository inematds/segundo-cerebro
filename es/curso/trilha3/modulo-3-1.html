🧭 Indicarle al agente el vault

Claude Code solo usa lo que ve. Si tu segundo cerebro —el vault generado por Graphify: está en un rincón del disco que nunca revisa, como si no existiera. El primer paso siempre es dejar el vault dentro del proyecto (o junto a él) y decirle al agente dónde está, justo al comienzo de la sesión.

🔰 ¿Eres nuevo aquí? Qué son «vault» y la carpeta de imports

O vault es la carpeta que generó la exportación de Obsidian: un .md por concepto, con backlinks [[nome-do-no]], más el GRAPH_REPORT.md. La convención del curso es guardarlo en una carpeta tipo graph-imports/<nome-do-grafo>/ dentro del proyecto, para que quede versionable y a la vista del agente.

No basta con que el vault esté en el disco: el agente necesita estar dirigido antes de empezar a recorrer el repositorio. La forma más sencilla es una frase de apertura que establece el vault como fuente primaria. El bloque de abajo es un prompt listo para copiar y pegar.

prompt de apertura (ilustrativo)

🎯 Objetivo: establecer el vault como fuente antes de cualquier pregunta.

O segundo cérebro deste projeto está em graph-imports/<nome-do-grafo>/ .
Lá tem um .md por conceito (com backlinks [[...]]) e o GRAPH_REPORT.md
com os god nodes. Use ESSE vault como fonte primária antes de varrer o repo.

✔ Cómo verificar: pide a continuación "lista los 5 god nodes de GRAPH_REPORT.md". Si responde con nombres reales del tu grafo, encontró el vault. Si inventa nombres genéricos, el camino es incorrecto.

⭐ Empezar por los god nodes

¿Por dónde empezar una pregunta? Por los god nodes — las entidades más conectadas del grafo, listadas en el GRAPH_REPORT.md. Son los hubs: entrar por uno de ellos arrastra el resto del mapa, porque casi todo pasa por ahí. Empezar por un nodo periférico es entrar por la puerta de atrás.

🔰 ¿Eres nuevo aquí? Qué es un «god node»

En el grafo, cada entidad (nodo) tiene un número de conexiones. Los god nodes son los campeones de conexión — "Context Window", los "Hooks", el "MCP" de una documentación, por ejemplo. Graphify ya los calcula y los vuelca en el GRAPH_REPORT.md, junto con preguntas sugeridas.

✓ Entrar por un hub

  • ✓Abarca más terreno de una sola vez.
  • ✓Trae consigo a los vecinos adecuados.
  • ✓El informe ya sugiere por dónde avanzar.

✗ Entrar por un nodo aislado

  • ✗Solo ves una parte aislada.
  • ✗Se necesitan muchos saltos para llegar a lo que importa.
  • ✗Es fácil detenerse antes de encontrar el contexto.

🔗 Dejar que el agente siga los backlinks

Entró por un god node, ¿y ahora qué? El truco está en dejar que el agente seguir los backlinks: los [[links]] que cada nota transmite a los conceptos vecinos. En vez de detenerse en el primer nodo, recorre la vecindad y prepara una respuesta conectada, no aislada.

Es exactamente lo que el vault está diseñado para permitir: cada .md apunta a los vecinos, así que el agente navega por el sentido — no posiciones de texto sueltas. Visualmente, el camino es este:

↑ La pregunta entra por el god node destacado; desde ahí, el agente sigue los backlinks hasta los vecinos (cian) y devuelve una respuesta que conecta los conceptos, no un párrafo aislado.

💬 Prompts que usan el mapa

Todo esto se convierte en hábito con un prompt bien armado. La diferencia entre "explica X" y un prompt que dirige al grafo es enorme: el segundo indica al agente que entre por el hub, siga los backlinks, cite las notas y se mantenga dentro del alcance del vault. El bloque de abajo es el copy-run principal de este módulo.

prompt-mapa (ilustrativo)

🎯 Objetivo: responder usando el mapa y citar la procedencia, sin recorrer el repo.

Use o vault em graph-imports/<nome-do-grafo>/ para explicar <tema>.
Comece pelo god node mais ligado a ele, siga os backlinks [[...]] até os
conceitos vizinhos e cite cada nota .md que usar. Não varra o resto do repo.

✔ Cómo verificar: la respuesta debe citar nombres de notas del vault (p. ej.: Context-Window.md) y los conceptos vecinos, no un párrafo genérico sin fuente. Sin citas = no usó el mapa.

✓ Prompt que usa el mapa

  • ✓Indica la carpeta exacta del vault.
  • ✓Pide que empiece por el god node.
  • ✓Exige citar las notas (procedencia).

✗ Prompt vago

  • ✗"Explica X" — sin decir dónde buscar.
  • ✗Deja que el agente recorra todo a ciegas.
  • ✗Respuesta sin fuente, difícil de verificar.

🛰️ Servir el grafo vía MCP (opcional)

Leer archivos markdown funciona, pero Graphify también puede servir el grafo como tools programáticas, mediante MCP. Así, el agente consulta el grafo de forma precisa (nodos vecinos de un nodo, camino más corto) en vez de depender solo del texto. Es opcional, pero muy útil para grafos grandes.

🔰 ¿Eres nuevo aquí? Qué es «MCP»

MCP (Model Context Protocol) es el estándar que permite que Claude Code llame a tools y leer resources de un servidor externo. Aquí, el servidor es el propio grafo: expone funciones como query_graph que el agente llama al responder.

iniciar el servidor MCP (ilustrativo)

🎯 Objetivo: ofrecer el grafo como tools, no solo como archivos.

# dentro do Claude Code (skill form):
/graphify . --mcp

# ou via terminal puro:
graphify --mcp

# tools expostas: query_graph · get_node · get_neighbors · shortest_path

✔ Cómo verificar: pídele "usa query_graph para listar los vecinos de <concepto>". Si llamar a la tool y devuelve los nodos conectados, el MCP está activo. Si responde con texto sin invocar una tool, el servidor no se inició.

🧪 Validar la respuesta con la fuente

Confía, pero verifica. El grafo guarda la procedencia de cada nodo —el archivo fuente del que salió la entidad— dentro del graph.json. Cuando el agente afirma algo, cierras el ciclo yendo desde el concepto hasta el doc-fuente original y comprobando si coincide. Es la mejor defensa contra las alucinaciones.

↑ El concepto afirmado conduce, por la procedencia del graph.json, hasta el documento fuente original, donde puedes verificar. Los documentos fuente no van al vault: se quedan en el proyecto.

1

Toma el concepto afirmado

Anota la afirmación central de la respuesta y el nodo (nota) que la respalda.

2

Sigue la procedencia en graph.json

Cada entidad registra de qué archivo de origen proviene. Ese es el puntero a la evidencia.

3

Abre el doc fuente y revisa

Si coincide, confianza total. Si no coincide, es una alucinación: corrige la nota o vuelve a generar el grafo.
