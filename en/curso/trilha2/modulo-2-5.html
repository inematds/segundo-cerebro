📂 Open folder as vault (manage vault)

The Graphify export left a folder full of markdown—but Obsidian won't find it on its own. You need to point it to the directory. This is done once, from the Manage vaults, choosing Open folder as vault and selecting the generated folder.

🔰 New here? What is a "vault"

A vault is simply a folder that Obsidian manages as a knowledge base. There’s no hidden database: they’re files .md in a directory. “Open a folder as a vault” means telling Obsidian: treat this folder as my base.

▶ STEP BY STEP · Obsidian interface (not a terminal command)

Objective: make Obsidian recognize the folder generated by Graphify as a navigable vault.

1

In Obsidian, look at the lower-left corner — the active vault icon.

2

Click it and choose Manage vaults… (manage vaults).

3

Select Open folder as vault (open folder as vault).

4

Choose the generated folder using the export — e.g.: ~/vault/graphify/claude-code.

How to verify: the left sidebar now lists the files .md — one per node. If the notes appear, the vault was recognized.

🧭 Navigate nodes and backlinks

Open a note-node any and follow the [[wikilinks]] inside it: each one leads to a neighboring concept. It’s the second brain in action — you explore the knowledge through relationships, not by typing searches.

🔰 New here? What is a "backlink"

A backlink is the way back: if the note Hooks mentions [[Subagentes]], Obsidian automatically shows, in the note Subagents, which Hooks points to it. You can navigate in both directions — who cites it and what it cites — without ever searching the text.

↑ You open a note and jumps through the backlinks to the neighborhood you need — each node knows its relatives. It’s like walking through the neighborhood, not consulting a list of addresses.

✓ Navigate by relationships

  • ✓One click on the backlink is the next idea.
  • ✓Finds neighbors you wouldn't even search for.
  • ✓The backlinks pane shows who cites the note.

✗ Search by text

  • ✗You need to guess the right word.
  • ✗Doesn’t reveal connections, only occurrences.
  • ✗Loses the context that gives it meaning.

🖼️ Open graph.canvas (communities)

In addition to a .md per node, the export generates a file graph.canvas. Open it in Obsidian: it draws the communities — the groups of concepts detected by the Leiden algorithm—like named boxes on a board. This is the corpus’s high-level view of its themes.

🔰 New here? What is a "canvas"

O Canvas is a native Obsidian feature: an infinite whiteboard where notes and groups become movable cards. Graphify uses this format to place each community as a named group — you see the themes side by side, not buried in the file list.

vault/ — open graph.canvas
~/vault/graphify/claude-code/
├── graph.canvas      ← abra ESTE: comunidades como grupos nomeados
├── Hooks.md
├── Subagentes.md
├── Context-Window.md
└── … (um .md por nó)

Use the canvas to choose where to start: each group is a topic. Click a community you're interested in and enter through one of its notes — from there, navigate through the backlinks (topic 2). The canvas gives you the overview; the backlinks give you the details.

4

🧷 Bring in/link the source documents

Each node is a summary of a concept—not the full text. The provenance (which file that concept came from) is recorded in the graph.json, but the source documents no are copied to the vault. The step that closes the loop is bringing these sources closer and adding, in each node note, a signpost pointing to the source document.

🔰 New here? What is "provenance"

Provenance is the source of each entity: which file Graphify read to create that node, and where in the file it found it. It lives in the graph.json (source-file field per entity). Without the explicit link, the node knows where it came from, but you can’t jump to the full text with one click.

↑ The node stays connected to its neighbors through backlinks (cyan), and gains a "source doc" sign pointing to the full file. The concept becomes an entry point to the entire text.

🌐 Obsidian's graph view (not the original graph)

Obsidian has a graph view own — that pretty little dot-and-line. Watch out for the confusion: it only draws the [[links]] among the markdown notes. It's a mirror from the vault, no Graphify's graph. The original typed relationships (with names and direction) live in the graph.json and in the view graph.html.

Graphify graph (original)

  • •Relationships typed: every edge has a name and direction.
  • •God nodes, communities, provenance.
  • •Lives in graph.json / graph.html.

Obsidian's Graph view (mirror)

  • •Only the [[links]] among notes.
  • •No relationship type or semantic direction.
  • •Markdown reflection — useful, but derived.

⚠️ Set expectations

If the graph view seems "poorer" than the graph.html of Graphify, it’s because it é — by design. To see the real graph (with types and directions), go back to the graph.html. The graph view is for browsing notes, not auditing the graph.

💬 Ask Claude Code to "wire" the sources

Doing topic 4 by hand, node by node, is a lot of work. The good news: Claude Code reads the graph.json and the vault folder — then you can delegate wire the sources to it with a single prompt. It finds where they came from, brings the documents into the vault, and writes the "source-doc" link in each note.

▶ PROMPT · paste into Claude Code, at the project root

Objective: bring the source documents into the vault and automatically link each node to its origin.

Bring the source documents into the vault at
~/vault/graphify/ and link each node to its source.

Steps:
1. Read the provenance in graph.json (the source-file field for each entity).
2. For each node, copy the source document into a subfolder
   called sources/ inside the vault.
3. In each node note’s Markdown file, add a "source doc" link
   pointing to the corresponding file in sources/.

Source of the original documents: 
Important: Obsidian’s graph view is just a mirror of the notes —
the true provenance lives in graph.json; use it as the source.

Replace the variables: <isto-voce-troca> = the name of your vault folder (e.g., claude-code) and the folder path with the original documents (e.g., ./claude-code-docs).

How to verify: open any node note in Obsidian — there should be a clickable "source-doc" link that opens the complete file inside sources/.

⚠️ Why stick with graph.json

If Claude tries to guess the source from the [[links]] from the graph view, it gets this wrong: that's a mirror, not the original graph. A provenance for each entity is only correct in the graph.json — that’s why the prompt requires using it.
