💬 Perguntar ao Claude Code usando o grafo

Com o vault no projeto, faça o agente responder usando o mapa em vez de varrer tudo.

O que é:

Deixar o vault dentro (ou junto) do projeto e dizer ao Claude Code onde ele está.

Por que:

Ele só usa o que enxerga — se o vault não está no contexto, é como se não existisse.

Conceitos:

Caminho do vault · contexto · projeto.

O que é:

Usar os god nodes do GRAPH_REPORT.md como ponto de partida das perguntas.

Por que:

Os hubs cobrem mais terreno — começar por eles puxa o resto do mapa junto.

Conceitos:

God node · hub · entrada.

O que é:

Pedir pra ele seguir os [[links]] de um conceito pros vizinhos.

Por que:

Respostas conectadas, não isoladas — o agente anda pela vizinhança em vez de parar no primeiro nó.

Conceitos:

Backlink · vizinhança · navegação.

O que é:

Prompt pronto — "use o vault em <pasta> pra explicar X e seus conceitos ligados, citando as notas".

Por que:

Direciona o agente ao grafo em vez de deixá-lo varrer arquivos no escuro.

Conceitos:

Prompt · citar notas · escopo.

O que é:

graphify --mcp expõe tools query_graph, get_node, shortest_path.

Por que:

O agente consulta o grafo programaticamente, sem depender só dos arquivos markdown.

Conceitos:

MCP · query_graph · resource.

O que é:

Ir do conceito ao doc-fonte ligado e checar se bate.

Por que:

Evita alucinação e fecha o ciclo: a procedência leva você de volta à evidência.

Conceitos:

Procedência · checagem · doc-fonte.

🏛️ Construindo um Claude OS command center

Transforme o vault num centro de comando: vários projetos, conhecimento e dúvidas num lugar só.

O que é:

Um vault principal que reúne projetos, conteúdo e o conhecimento importado num sistema coerente.

Por que:

O stack brilha quando faz parte de um todo — não como grafos soltos.

Conceitos:

Command center · vault principal · sistema.

O que é:

Estruturar o vault em projetos/áreas e uma pasta de imports do grafo.

Por que:

Cada coisa no lugar, fácil de achar — e fácil do agente navegar.

Conceitos:

PARA-like · projetos · imports.

O que é:

Cada novo Graphify entra numa subpasta de import e se liga ao que já existe.

Por que:

O cérebro cresce de forma controlada, com curadoria, em vez de virar despejo.

Conceitos:

Subpasta · ligação · curadoria.

O que é:

Criar notas-ponte que ligam o conhecimento importado aos seus projetos reais.

Por que:

Tira o grafo do vácuo — a tese do vídeo: conhecimento integrado vale mais que isolado.

Conceitos:

Nota-ponte · contexto · integração.

O que é:

Usar o agente pra consultar, resumir e atualizar o vault do command center.

Por que:

O centro fica vivo, não estático — ele edita junto com você.

Conceitos:

Copiloto · consultar · manter.

O que é:

Pra code bases ou consultas pontuais, parar no Graphify pode ser melhor.

Por que:

Nem todo caso pede Obsidian — montar um centro só pra uma pergunta é overhead.

Conceitos:

Trade-off · silo · simplicidade.

🧭 Código vs documentos: quando parar no Graphify

Nem todo grafo precisa ir pro Obsidian. Aprenda a decidir onde parar.

O que é:

Apontar o Graphify a um repositório de código (extração AST via tree-sitter).

Por que:

Mapeia funções/módulos sem API key — rápido e barato.

Conceitos:

Code base · AST · tree-sitter.

O que é:

Apontar a docs/PDFs (extração semântica via LLM).

Por que:

Capta conceitos e relações de texto — não só a estrutura literal.

Conceitos:

Corpus · LLM · semântica.

O que é:

Pra explorar um code base pontual, o graph.html + query já bastam.

Por que:

Levar pro Obsidian seria overhead quando você só quer uma resposta rápida.

Conceitos:

Parar · graph.html · query.

O que é:

Quando o conhecimento precisa conviver com seus projetos e notas.

Por que:

É o caso de uso do segundo cérebro integrado — não um grafo isolado.

Conceitos:

Integrar · vault · contexto maior.

O que é:

Usar graphify update/--watch conforme o código/docs mudam.

Por que:

O grafo não envelhece — fica fiel à fonte.

Conceitos:

Update · watch · sync.

O que é:

Pesar tempo de extração, ruído do grafo e esforço de manter o vault.

Por que:

Decisão consciente, não hype — o custo é real.

Conceitos:

Custo · ruído · manutenção.

🛠️ Manutenção, atualização e solução de problemas

Mantenha o grafo e o vault saudáveis e saiba o que fazer quando algo dá errado.

O que é:

graphify update . reprocessa só o que mudou; re-exportar o --obsidian regenera o vault.

Por que:

Manter atual sem refazer tudo do zero.

Conceitos:

Update · re-export · incremental.

O que é:

O export Obsidian é regenerado do zero — edições manuais nas notas geradas se perdem.

Por que:

Manter suas notas em pastas separadas (imports vs suas) protege seu trabalho.

Conceitos:

Regeração · separação · imports.

O que é:

Rodar uv tool update-shell e reabrir o terminal.

Por que:

O binário não está no PATH — o shell precisa recarregar.

Conceitos:

PATH · shell · uv.

O que é:

Setar ANTHROPIC_API_KEY pro uso headless; dentro do /graphify não precisa.

Por que:

Distinguir os dois caminhos evita erro de chave onde ela nem é necessária.

Conceitos:

API key · headless · skill.

O que é:

Limpar a fonte, usar --mode deep ou re-escopar.

Por que:

Melhora entidades/relações — corpus melhor, grafo melhor.

Conceitos:

Ruído · --mode deep · escopo.

O que é:

Commitar graphify-out/ (ou o vault) no git; usar export do próprio curso pra salvar progresso.

Por que:

Reprodutível e seguro — você não perde o que construiu.

Conceitos:

Git · backup · reprodutibilidade.
