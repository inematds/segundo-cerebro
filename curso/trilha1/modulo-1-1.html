🤖 O agente e a "memória" dele

O Claude Code é um agente de IA que vive no seu terminal. Diferente de um chat comum, ele age: lê arquivos do projeto, edita código, roda comandos e encadeia passos para concluir uma tarefa. Quando falamos de "memória" dele, estamos falando de tudo que ele consegue ter diante dos olhos na hora de responder.

🔰 Novo aqui? O que é um "agente"

Um LLM é o modelo de IA que roda atrás do ChatGPT/Claude. Um agente é esse modelo com ferramentas: coisas que ele faz sozinho — abrir um arquivo, rodar um comando, editar uma linha. O Claude Code é exatamente isso, dentro do seu terminal.

A memória do agente tem duas fontes: a conversa atual (o que você falou e o que ele leu nesta sessão) e o que você aponta para ele consultar (arquivos, regras, índices). O problema: a conversa some quando a sessão termina, e apontar "o repositório inteiro" raramente cabe. É essa lacuna que o curso resolve.

✓ Memória de verdade

  • ✓Persiste entre sessões.
  • ✓É consultável: o agente acha o que precisa.
  • ✓Guarda relações, não só texto solto.

✗ Só a sessão

  • ✗Esquece tudo ao fechar.
  • ✗Recomeça do zero em projetos grandes.
  • ✗Reaprende o mesmo contexto toda vez.

🪟 A janela de contexto e seus limites

A janela de contexto é o quanto de texto o modelo consegue ler de uma vez. É medida em tokens — pedaços de palavra (mais ou menos 3 a 4 caracteres cada). É grande, e os modelos mais novos chegam a 1 milhão de tokens, mas ainda assim é finita: um repositório inteiro, com centenas de arquivos, raramente cabe junto.

🔰 Novo aqui? O que é um "token"

Token é a unidade que o modelo lê. A palavra "memória" pode virar 2 ou 3 tokens. Quanto mais você enfia na janela, mais ele "paga" para ler — e há um teto. Por isso escolher o que ler importa tanto.

↑ Cabe um punhado de arquivos na janela; o repositório inteiro transborda. Por isso o agente precisa escolher bem o que ler — e um mapa ajuda nessa escolha.

🔍 Por que buscar por texto (grep) não basta

Quando o agente não tem um mapa, a ferramenta dele é o grep: a busca literal por uma palavra dentro dos arquivos. Ele acha onde o termo aparece — mas não sabe o que se relaciona com o quê, nem o porquê. "Achar" não é "entender".

🔰 Novo aqui? O que é "grep"

grep é um comando clássico de terminal que procura uma palavra em arquivos e devolve as linhas onde ela aparece. Útil, mas burro: não conhece sinônimos, contexto ou conexões.

↑ O grep devolve uma pilha de posições; o mapa devolve o conceito e seus vizinhos. É a diferença entre uma lista de endereços e um mapa do bairro.

🧩 O que é um "segundo cérebro"

"Segundo cérebro" é um termo de produtividade pessoal: uma base de conhecimento externa e organizada que você consulta em vez de tentar lembrar de tudo. Aqui, adaptamos a ideia para o agente: o segundo cérebro é o grafo + o vault que guardam o entendimento de um projeto fora da sessão efêmera.

💡 A ideia central do curso

Tirar o conhecimento de dentro de uma conversa que some e colocá-lo num lugar persistente, navegável e consultável — por você e pelo agente.

  • •Persistente: não some quando a sessão fecha.
  • •Navegável: conceitos ligados por links, não arquivos soltos.
  • •Consultável: o agente acha o que precisa sem varrer tudo.

🔰 Novo aqui? O que é "PKM"

PKM (Personal Knowledge Management, gestão pessoal de conhecimento) é a prática de guardar e conectar o que você aprende. O Obsidian é uma ferramenta de PKM — e é por isso que ele encaixa tão bem aqui.

📝 O que o Claude Code já tem nativo

O Claude Code não é amnésico de fábrica. Ele já lê um arquivo CLAUDE.md na raiz do projeto com instruções e preferências, e tem sua própria memória. Isso é ótimo para regras ("sempre rode os testes", "use português") — mas não é um mapa de um repositório inteiro.

CLAUDE.md (exemplo ilustrativo)
# Projeto X

- Sempre responda em português.
- Rode os testes antes de dizer "pronto".
- A documentação de referência está em ./docs.

Repare: o CLAUDE.md diz "a doc está em ./docs", mas não diz como os conceitos da doc se conectam. É aí que o Graphify entra — ele não compete com o nativo, ele complementa: o nativo guarda regras; o grafo guarda o mapa.

🎯 A promessa do stack Graphify + Obsidian

Juntando tudo: o Graphify cria o mapa a partir de um repositório ou de documentos; o Obsidian guarda esse mapa como markdown navegável; o Claude Code consulta o mapa no contexto do seu projeto. Juntos, são o segundo cérebro.

1

Graphify cria o mapa

Extrai entidades, relações e comunidades de uma fonte. Saída: o grafo.

2

Obsidian guarda o mapa

Um markdown por conceito, com backlinks. Persistente e navegável.

3

Claude Code consulta o mapa

Responde sobre o projeto no contexto certo, sem reler tudo.
