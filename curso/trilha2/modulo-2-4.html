🚩 O flag --obsidian e --obsidian-dir

No módulo 2.3 você gerou o graph.json. Agora vamos virá-lo num vault de Obsidian. O gatilho é uma flag: dentro do Claude Code você roda o /graphify na sua fonte com --obsidian, e isso liga o export de vault. O --obsidian-dir diz onde os arquivos vão cair.

🔰 Novo aqui? Skill vs headless

O Graphify tem duas formas. A skill é o slash command /graphify rodado dentro do Claude Code. O headless é o terminal puro, com graphify extract. São o mesmo motor, mas só a skill conhece --obsidian.

⚠️ A pegadinha que muita gente erra

--obsidian não existe no graphify extract headless. Se você tentar graphify extract . --obsidian no terminal, ele não reconhece a flag. O export de vault é skill-only.

⚡ Prático — copiar e rodar

Objetivo: transformar o grafo da sua fonte de docs num vault de Obsidian, escolhendo a pasta de saída.

Claude Code (skill /graphify)
/graphify ./claude-code-docs --obsidian --obsidian-dir ~/vault/graphify/claude-code

./claude-code-docs e ~/vault/graphify/claude-code são <isto-voce-troca> — ajuste para a sua fonte e o seu destino.

Como verificar: liste a pasta de destino e confira que apareceram arquivos.

ls ~/vault/graphify/claude-code | head

🎯 Escolher o destino do vault

O --obsidian-dir define a pasta onde o vault nasce. Sem ele, a skill cria um diretório próprio — uma espécie de quarentena isolada, longe do seu vault principal. É o comportamento mais seguro, mas escolher o destino dá organização.

🔰 Novo aqui? O "default isolado"

Sem --obsidian-dir, o export não invade o seu vault de trabalho — ele vai para uma pasta dedicada que você pode inspecionar (e apagar) sem risco. Quando estiver confiante, aponte um destino fixo.

duas variantes
# destino que VOCÊ escolhe (organizado)
/graphify ./claude-code-docs --obsidian --obsidian-dir ~/vault/graphify/claude-code

# sem --obsidian-dir: a skill cria uma pasta própria (quarentena)
/graphify ./claude-code-docs --obsidian

↑ As duas funcionam. A primeira é previsível (você sabe onde achar); a segunda é à prova de bagunça — bom para o primeiro teste. O caminho ~/vault/graphify/claude-code é <isto-voce-troca>.

🧾 O que é gerado (md por nó + graph.canvas)

O export tem duas peças. A primeira: um arquivo .md por nó do grafo, cada um com [[wikilinks]] para os nós relacionados (que viram backlinks). A segunda: um graph.canvas com as comunidades agrupadas. Juntas, são o vault navegável.

🔰 Novo aqui? O que é um "wikilink"

Um wikilink é a sintaxe [[nome-da-nota]] do Obsidian: um link interno de uma nota para outra. Quando A linka B, o Obsidian mostra em B um backlink ("quem aponta para mim"). É assim que o conhecimento fica navegável por relações.

🔰 Novo aqui? O que é um "canvas"

Um canvas (arquivo .canvas) é um quadro visual do Obsidian onde notas viram caixas que você arranja livremente. O graph.canvas usa isso para mostrar cada comunidade como um grupo nomeado — a visão macro do corpus.

↑ Um nó do grafo = uma nota .md; as relações viram [[wikilinks]]; as comunidades viram grupos no graph.canvas. Os números (591 nós) são ilustrativos — vêm da execução do vídeo.

♻️ Regeração: roda de novo, refaz tudo

O export é regenerado do zero a cada execução, sempre a partir do graph.json. Não há merge manual: o grafo é a fonte de verdade, e o vault é apenas um reflexo dele. Por isso a operação é idempotente — rodar duas vezes seguidas dá o mesmo resultado.

🔰 Novo aqui? "Regeração" e "idempotente"

Regeração = o vault é recriado inteiro a cada run, não atualizado parcialmente. Idempotente = repetir a operação não muda o resultado além da primeira vez. Em troca, você não precisa pensar em "estado anterior" — re-rode à vontade.

⚠️ Não edite as notas geradas à mão

Como o export é refeito do zero, qualquer edição manual nas notas geradas é perdida na próxima execução. Quer mudar o conteúdo do vault? Mude a fonte (os docs) ou o graph.json e re-rode — nunca o markdown de saída.

✓ Seguro

  • ✓Re-rodar quantas vezes quiser.
  • ✓O vault sempre reflete o grafo atual.
  • ✓Sem estados intermediários inconsistentes.

✗ Se perde

  • ✗Notas editadas à mão são sobrescritas.
  • ✗Anotações dentro das notas geradas somem.
  • ✗Não há merge: é tudo ou nada.

↑ Cada run reconstrói o vault inteiro a partir do grafo. O lado bom: ele nunca fica "desatualizado". O lado a lembrar: edições manuais não sobrevivem — a fonte é o grafo, não o markdown.

📚 --wiki como alternativa

Além do vault nó-a-nó, existe um segundo formato: --wiki. Em vez de uma nota por nó, ele gera artigos por comunidade com um index.md de entrada — uma leitura no estilo Wikipédia, boa para quem (humano ou agente) prefere ler textos contínuos a navegar caixas.

⚡ Prático — copiar e rodar

Objetivo: gerar a versão wiki (artigos por comunidade) da mesma fonte, para comparar com o vault.

Claude Code (skill /graphify)
/graphify ./claude-code-docs --wiki

./claude-code-docs é <isto-voce-troca> — aponte para a sua fonte.

Como verificar: procure o index.md e os artigos na pasta de saída.

ls ~/vault/graphify/claude-code | head

🔰 Vault ou wiki — qual usar?

Use o vault (--obsidian) quando quiser navegar por relações dentro do Obsidian. Use a wiki (--wiki) quando quiser ler artigos temáticos. Não são exclusivos — você pode gerar os dois e escolher depois.

👀 Conferir o vault gerado

Antes de abrir o Obsidian, faça uma checagem rápida no sistema de arquivos: olhe a pasta de destino, conte os arquivos .md e confirme que o graph.canvas está lá. Isso pega exportações vazias ou truncadas cedo, antes de você investir tempo na ferramenta.

⚡ Prático — copiar e rodar

Objetivo: confirmar que o export produziu as notas e o canvas no destino certo.

terminal
ls ~/vault/graphify/claude-code | head
ls ~/vault/graphify/claude-code/*.canvas

~/vault/graphify/claude-code é <isto-voce-troca> — use o destino que você passou em --obsidian-dir.

Como verificar: o primeiro comando deve listar vários arquivos .md; o segundo deve achar exatamente um graph.canvas. Lista vazia = export falhou; re-rode o passo do tópico 1.
